# NewLife.AB 架构设计

**项目**：NewLife.AB — 罗克韦尔 / Allen-Bradley Logix 通信协议库  
**版本**：v1.0  
**日期**：2026-11-11  
**配套**：[需求文档.md](需求文档.md)

---

## 1. 原则

| 原则 | 做法 |
|------|------|
| 只依赖 BCL 和 NewLife | 协议代码使用 `TcpClient` / `NetworkStream`。日志用 `XTrace`，驱动用 NewLife.IoT。不引入第三方协议栈 |
| 公开码 | 服务码、类型码、封装命令来自 CIP Volume 1/2 和 Logix 5000 Data Access 的公开描述。不抄 Studio 5000 源码，也不编造服务号 |
| 和 Omron 同形 | `Protocols` 放报文和客户端，`Drivers` 放 IoT 驱动。同步 `lock`，异步 `SemaphoreSlim`，异步等待使用 `ConfigureAwait(false)` |
| 可测 | `LogixServer` 实现同一套报文。测试连到 `127.0.0.1` 的临时端口 |
| 失败要看得见 | 不支持的 PCCC 直接抛 `NotSupportedException`。类型不符不静默转换 |

目标框架：`net45`、`net461`、`netstandard2.0`、`netstandard2.1`。因此不用 `Span<T>`、`BinaryPrimitives`、`Array.Empty`（net45 没有）和只存在于较新运行时的 API。小端读写在 `BinaryBuffer` 里手写。

## 2. 分层

```
应用 / Test 控制台 / 星尘
        │
        ▼
AbDriver、AbNode、AbParameter          NewLife.IoT.DriverBase
        │
        ▼
LogixClient（同步 + 异步）
  地址 LogixAddress、值 LogixValue、身份 LogixIdentity
        │
        ▼
CipMessage、CipPath、EipPacket、EipCommonPacket
        │
        ▼
TcpClient  ←→  LogixServer（测试）或真实 Logix CPU
```

一条读请求的字节顺序：

```
EtherNet/IP 头 24 字节
  命令 0x006F SendRRData
  会话句柄
  发送方上下文
通用包
  空地址项 0x0000
  未连接数据项 0x00B2
    Unconnected Send 0x52
      路径：类 0x06 实例 1
      嵌入的 Read Tag 0x4C
        路径：0x91 + 标签名 [+ 0x28 下标]
        数据：元素个数
      路由：0x01, 槽号
```

已连接模式去掉 Unconnected Send。Forward Open 成功后，SendUnitData（0x0070）使用连接地址项 0x00A1 和连接数据项 0x00B1，数据项前两个字节是序号。

## 3. 主要类型

| 类型 | 职责 |
|------|------|
| `EipPacket` | 24 字节封装头。命令、长度、会话、状态、8 字节上下文、选项 |
| `EipCommand` / `EipStatus` | 封装命令和状态，含会话无效 0x0064 |
| `EipCommonPacket` | SendRRData / SendUnitData 的通用包 |
| `CipMessage` | 请求：服务、路径字数、路径、数据。应答：服务\|0x80、保留 0、通用状态、扩展状态、数据 |
| `CipPath` | 类/实例、端口、符号段、元素段、路由字符串 |
| `CipService` / `CipDataType` / `CipStatus` | 公开常量 |
| `LogixAddress` | 解析地址并生成符号路径 |
| `LogixValue` | 按类型码解码。结构 0x02A0 再读 2 字节句柄 |
| `LogixClient` | 连接、重试、标签 API |
| `LogixServer` | 内存标签表和上述服务 |
| `PcccLegacy` | 唯一的 PCCC 入口，固定失败 |
| `AbDriver` | IoT 驱动。`Length` 是字节数 |

`0x4E` 和 `0x52` 各有两个含义。分发时先看路径是不是连接管理器（类 0x06 实例 1）：

- 是：`0x52` 为 Unconnected Send，`0x4E` 为 Forward Close，`0x54` 为 Forward Open
- 否：`0x52` 为分段读，`0x4E` 为 Read Modify Write，`0x4C` / `0x4D` / `0x53` 为标签服务

## 4. 地址和路径

`LogixAddress.Parse` 的顺序：

1. 去掉两端空白
2. 第一个冒号前若是类型名，记为类型提示并剪掉。`Program` 不是类型名
3. 按不在括号内的点号切开
4. 若最后一段全是数字，则它是位号，不进入 CIP 路径
5. 每一段里的 `[n]` 或 `[n,m]` 变成元素段

`Program:MainProgram.Tag` 得到两段符号：`Program:MainProgram` 和 `Tag`。这是 Logix 对程序作用域标签的符号段写法，冒号属于第一段的名字。

符号段 `0x91` 在字符数为奇数时补 0，保证路径按字对齐。元素下标不超过 255 时用 `0x28`，否则用 `0x29` 或 `0x2A`。

存储键是符号名用点连起来，不含下标和位。模拟器用这个键找标签，下标再在元素数组里取。

## 5. 客户端生命周期

`Connect`：

1. `TcpClient.Connect`，超时 `ConnectTimeout`
2. Register Session。数据是版本 1 和选项 0。会话句柄在应答头里
3. 若 `ConnectedMessaging`，发 Forward Open。连接路径是路由再加消息路由器（类 2 实例 1）。连接参数 `0x43F4`（500 字节、可变、点到点），传输触发 `0xA3`，RPI 100ms
4. 应答前 4 字节作为之后 SendUnitData 的 O→T 连接 ID

`Close`：已连接则 Forward Close，再 UnRegister Session（该命令没有应答），然后关套接字。

普通读写拿同步锁，调用 `Execute`：

- 未连接且 `RouteToSlot`：请求先包进 Unconnected Send
- 已 Forward Open：走 SendUnitData，不再套 Unconnected Send
- 应答状态非 0 抛 `CipException`
- 状态 0x0064：重新 Register Session；如果开了连接模式，再 Forward Open
- `IOException`、`SocketException`、超时：关掉套接字，等待 `重试次数 × RetryDelayMilliseconds` 后重连。默认基数 1000 毫秒，最多 3 次

异步方法是独立的一套读写，不在异步路径里调用同步 `Execute`，避免锁重入。两种路径不要对同一个实例同时使用。

分段读：第一次用 Read Tag。状态若是 0x06，记下类型头，按已收到的元素字节数作为下一次 Read Tag Fragmented 的偏移，直到状态为 0。每次应答都带类型头，拼的时候只追加元素字节。

分段写：元素字节超过 `WriteFragmentSize` 时，偏移按本次发送的字节数增加，元素个数保持为总个数。

STRING：`StringStructureHandle` 有值就用它。否则查缓存，缓存没有就先读标签。标签不存在（0x05）时句柄用 0，随后的写入若控制器也没有该标签，仍会失败。模拟器在自动建点时把句柄 0 记成 `DefaultStringHandle`（0x00CE）。

位：路径里没有位号。先确定元素宽度（类型提示或先读），再按小端生成 OR / AND 掩码。置位 bit2、清零 bit5 的 4 字节掩码与公开示例一致：OR 为 `04 00 00 00`，AND 为 `DF FF FF FF`。

多标签：`ReadTags` 把若干 Read Tag 打进服务 0x0A，偏移从请求数据起点算。外层状态允许 0x00 或 0x1E，每个子应答单独检查。带位号的地址不放进包，单独读。异步的 `ReadTagsAsync` 逐个等待，结果相同，不打包。

## 6. 模拟器

每个 TCP 连接有自己的会话号和 Forward Open 状态。标签表进程内共享，键不区分大小写。

- 未知命令：封装状态 0x0001
- 注册版本不是 1：0x0069
- `InvalidateSessionOnce`：下一次显式报文返回 0x0064，并丢掉该会话
- `RequiredSlot`：Unconnected Send 的路由里必须有端口 1 且链路等于该槽，否则 CIP 0x04
- `ForceGeneralStatus`：所有 CIP 服务直接返回这个状态
- `MaxResponseBytes`：元素数据超过它就返回 0x06，并按元素大小向下取整
- `AutoCreateTags`：只影响模拟器。真实 CPU 不会因为写入而出现新标签
- 已有标签的类型必须一致，否则 0xFF / 0x2107
- 下标加元素个数超出长度：0xFF / 0x2105
- 多维下标：0x03。真实控制器是否接受取决于数组维数，客户端仍会把下标编码进路径

身份对象的属性顺序是厂商号、设备类型、产品代码、主次版本、状态、序列号、短字符串产品名。ListIdentity 在此之前还有协议版本和 sockaddr（端口和地址是大端）。

## 7. 驱动

`AbDriver` 的特性名是 `ABPLC`。`OpenAsync` 要求 `host:port`，用最后一个冒号拆端口。第一个节点创建 `LogixClient` 并连接，之后的节点只增加计数。计数回到 0 时关闭。

读：全部是单个元素时调用 `ReadTags`，否则按点读取。`Length` 除以类型宽度得到元素个数，不足一个元素时按 1 个读。STRING 始终读 1 个。

写：按 CLR 类型调用对应的 `Write*`。`Byte[]` 需要点位类型或地址里的类型提示。其它类型在接触套接字之前抛 `ArgumentException`。

## 8. 扩展 PCCC 时改哪里

不要在 `LogixClient` 里假装支持文件地址（如 `N7:0`）。以后如果要做 SLC / PLC-5：

1. 继续用现有的注册会话和 SendRRData
2. 新增客户端，向 PCCC 对象发送服务 `PcccLegacy.ExecutePccc`（0x4B）
3. 在嵌入数据里放 DF1 命令，不复用 Read Tag 的符号路径
4. 模拟器单独实现这套命令，并在 README 里把“不支持”改成具体型号

在那之前，`PcccLegacy.ThrowNotSupported` 是唯一入口。
